# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

###  Данные
В приложении используются две сущности, которые описывают данные, — товар и покупатель. Их можно описать такими интерфейсами:

Товар:
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}

Покупатель:
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
###  Модели данных
#### Класс Product
Отвечает за управлением товаров

Поля класса: 
`products: IProduct[]` - хранит массив всех товаров
`previewProduct: IProduct | null`- выбранный товар для подробного отображения
`events: EventEmitter`- экземпляр EventEmitter для отправки событий

Конструктор: 
`constructor(events: EventEmitter)` - принимает экземпляр EventEmitter

Методы класса:
`setProducts(products: IProduct[]): void` - сохраняет массива товаров. Отправляет событие `card:changed`
`getProducts(): IProduct[]` - получение массива товаров из модели.
`getProductById(id:string): IProduct | undefined` - получение одного товара по его id.
`setPreviewProduct(product:IProduct | null): void` - сохраняет товар для подробного отображения. Отправляет событие `preview:changed`
`getPreviewProduct():IProduct | null` - получение товара для подробного отображения.



#### Класс Cart 
Отвечает за управлением товарами в коризине

Поля класса:
`cart: IProduct[]` хранит массив товаров, выбранных покупателем для покупки.

Конструктор: 
`constructor(cart: IProduct[] = [])` создает экземпляр корзины. Принимает параметр - массив товаров, по умолчанию пустая корзина. 
`events: EventEmitter`- экземпляр EventEmitter для отправки событий

Методы класса:
`getProductsInCart(): IProduct[]` - получение массива товаров, которые находятся в корзине.
`addProductToCart(product: IProduct): void`- добавление товара, который был получен в параметре в массив корзины. Отправляет событие `cart:changed`
`removeProductFromCart(id:string):void`- удаление товара, полученного в параметре из массива корзины.
`clearCart():void` - очистка корзины. Отправляет событие `cart:changed`
`getTotalPrice():number`- получение стоимости всех товаров в корзине.
`getProductCount():number`- получение количества товаров в корзине.
`checkCartById(id:string):boolean` - проверка наличия товара в корзине по его id.


#### Класс Buyer 
Отвечает за данные о покупателе

Поля класса:
`payment: TPayment` - оплата, `email: string` - почта, `phone: string` - телефон, `address: string` - адрес
`events: EventEmitter`- экземпляр EventEmitter для отправки событий

`constructor(events: EventEmitter)` - принимает экземпляр EventEmitter

Методы класса:
`setPayment(payment: TPayment): void` - сохранение оплаты и отправляет событие `buyer:changed`
`setEmail(email: string): void` - сохранение почты и отправляет событие `buyer:changed`
`setPhone(phone: string): void` - сохранение номера телефона и отправляет событие `buyer:changed`
`setAddress(address: string): void` - сохранение адреса и отправляет событие `buyer:changed`
`getData(): IBuyer` - получение всех данных покупателя; 
`clearData():void` - очистка данных покупателя;
`checkData():boolean` - валидация данных покупателя.

Конструктор:

Методы:
`set catalog(items: HTMLElement[])` - сохраняет элементы каталога

Управляет модальными окнами. Наследует класс `Component`. Интерфейс `IModal` получает содержимое для отображение.

`closeButton: HTMLButtonElement` - кнопка для закрытия модального окна

Методы:
`set total(value: number)` - устанавливает текст с информацией о списанной сумме

Управляет отображением корзины товаров. Наследует класс `Component`. Интерфейс `IBasket` получает список элементов корзины и общую сумму.

Методы:
`set itemsList(items:HTMLElement[])` -сохраняет список товаров в корзине (при пустой корзине показывает сообщение и блокирует кнопку)

`set counter(value:number)` - устанавливает количество товара в корзине

`set image(value:string)` - отображает товары с использованием метода `setImage` наследуемого от `Component`

`_inBasket:boolean` - внутреннее состояние наличия товара в корзине

Конструктор:
`events:IEvents, container:HTMLElement`- принимает объект событий и контейнер для рендеринга. На кнопку удаления вешается слушатель, который вызывает соответсвующуе событие `cart:removeFromBasket`, `cart:addToBasket`

Методы:
`set description(value:string)` - устанавливает описание товара
`set category(value:string)`- устанавливает категорию товара и добавляет соответствующий CSS-класс
`set image(value:string)`- устанавливает изображение товара
`set inBasket(value:string)`- устанавливает наличие в корзине и меняет текст кнопки 
`set price(value:number | null)`- устанавливает цену товара(если `null`, то отключает кнопку)

Методы:

`updateSubmitButton()` - обновляет состояние кнопки отправки 
`showErrors(errors: string[])` - показывает ошибки валидации в форме

#### Класс OrderForm
Реализует форму оформления заказа. Наследует класс `Form` с интерфейсом `IOrder`, который определяет струтуру данных: способ оплаты и адрес.

Поля класса:
`сardButton:HTMLButtonElemet` - кнопка выбора оплаты картой
`cashButton:HTMLButtonElemet` - кнопка выобра оплаты наличными
`addressInput:HTMLInputElemet` - поле ввода адреса
`selectedPayment:string` - выбранный способ оплаты

Конструктор:
`events:IEvents, container:HTMLElement`- принимает объект событий и контейнер для рендеринга. Инициализирует элементы и вызывает метод `init()`

Методы:
`init()` - добавляет обработчики клика на кнопки оплаты и ввода поля адреса
`updateSubmitButton()` - обновляет визуальное состояние кнопок оплаты в зависимости от выбранного способа оплаты, удаляя или добавляя CSS-класс `button_alt-active`
`isValid():boolean` - проверяет, что оба поля заполнены
`submit()` - отправляет данные формы через событие `order:next`
`validate():void` - выполняет валидацию полей, показывает ошибки и обновляет кнопку отправки

Методы:
`init()` - добавляет обработчики ввода на поля для валидации
`isValid():boolean` - проверяет, что оба поля заполнены
`submit()` - отправляет данные формы через событие `order:submit`
`validate():void` - выполняет валидацию полей, показывает ошибки и обновляет кнопку

### Презентер

Презентер состоит из обработчиков событий и находится в файле `main.ts`. Организует взаимодействие между моделями, слоем представления и сервером. Презентер обрабатывает события, а не генерирует их.

#### События:

`card:changed`- изменение каталога товаров. 
Получает массив товаров из модели, создает карточки католога собработчиком клика и с использованием шаблона. Устанавливает изображения, цены, название, id, категории. Обновляет отображение галереи товаров.
`preview:changed`- изменение выбранного товара для просмотра. 
Проверяет наличие товара в корзине, создает карточку предпросмотра с полной информацией о товаре, устанавливает состояние кнопки корзины и открывает модальное окно.
`card:select`-выбор карточки для просмотра.  Устанавливает выбранный товар как текущий для предпросмотра в модели данных.
`cart:addToBasket`-добавление товара в коризин. 
Находит товар по `id` в модели продуктов, добавляет в модель корзины и закрывает модальное окно.
`cart:removeFromBasket`-удаления товара из корзины. 
Находит товар по `id` в модели продуктов, удаляет из модели корзины и закрывает модальное окно.
`cart:changed`-изменение содержимого корзины. Обновляет счетчик товаров в шапке.
`cart:checkout`- начало оформления заказа. 
Создает и отображает форму заказа с полями для адреса и способа оплаты.
`order:next`- переход к следующей форме заказа. 
Сохраняет данные оплаты и адреса в модели покупателя, создает и отображает форму контактов.
`order:submit`-завершение оформления заказа. 
Сохраняет контактные данные покупателя, рассчитывает итоговую сумму, очищает корзину, создает и отображает окно успешного оформления 
`success:close`-закрытие окна успешного оформления. 
`buyer:changed`- изменение данных покупателя. Проверяет полноту заполнения всех обязательных полей. Обеспечивает синхронизацию состояния данных между формами и моделью.
